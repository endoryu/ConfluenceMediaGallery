# Proposal: Viewerズーム・パン機能のV1格上げ(Phase 2実装)

- 起案: Claude Code(2026-09-20)
- 契機: ユーザー要望「modalに拡大機能を追加したい」(2026-09-20)
- 状態: 裁定待ち
- 影響: L2(V1仕様書)のスコープ表・§7・§16・§18、L3(Phase2_Spec)のWU追加。**課金面・scope・manifest・恒久禁止事項への影響なし**(追加要求ゼロ、表示中Originalのtransformのみ)

## 1. 現状と変更理由

現行L2 §2のスコープ表は「画像の独自ズーム/パンUI、1:1表示」を**V1.1候補(スコープ外)**とする。一方§7.3は「新しい画像の表示状態は毎回`fit`に戻す」とズーム状態の存在を前提としており、Phase 2のWU-2でOriginal(原寸)を常にロードするため、拡大素材・実装基盤は揃っている。ユーザー要望によりV1範囲(Phase 2)へ格上げする。

推奨実装をPhase 2とする理由: ①Original既ロードで追加転送・追加API要求ゼロ ②ナビゲーション(WU-3)と操作系を同時設計でき手戻りがない ③V1対象がデスクトップChrome/Edgeのため操作系が小さく1 WU相当。

### 2.3 §7.8 新設(§7.7 音声の後)

```diff
+### 7.8 ズーム・パン
+
+画像のみ対象(動画・音声はnative controls)。状態は `fit`(既定)と任意倍率のzoomの2系統とし、ナビゲーション・画像差し替え時は毎回 `fit` に戻す(Section 7.3)。
+
+- 操作: wheel(カーソル位置基準。トラックパッドのピンチはブラウザがCtrl+wheelとして配送)、ダブルクリックで `fit`⇄100%(intrinsic 1:1)トグル、zoom中のドラッグでパン、キーボード `+`/`-`/`0`。
+- 実装: 表示中画像のCSS transform(translate+scale)のみで行い、**追加のメディア要求を発行しない**。変化は即時(transition不使用 — 恒久禁止事項)。
+- 倍率範囲: `fit`〜400%(Section 18)。パンは画像端でクランプする。
+- zoom中も前後移動・Esc・閉じるは有効(操作すると次画像は `fit`)。
+- 縮退段階(Section 11.1)の影響を受けない(新規要求を伴わないため全段階で有効)。
+- アクセシビリティ: キーボードのみで全操作可能(Section 13.4)。ズームボタンUIは置かず、操作はwheel/キーボード/ダブルクリックとする(コントロール最小の原則)。
```
